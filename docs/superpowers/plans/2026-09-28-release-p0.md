# Release P0 repair

Scope: repair the two P0 items approved in the project assessment. Preserve existing UI layout edits. No real executor integration or production data changes.

Design: the workflow engine owns all new release execution. Public endpoints delegate to it; legacy jobs are imported conservatively instead of executed by a second engine. Repository transactions synchronize release/execution state and terminal task updates. Execution lock versions fence stale workers; renewable leases cancel work when ownership is lost. Persist each deployment before invoking the executor, reuse its key on uncertain outcomes, and skip completed services on recovery. An executor must durably deduplicate by key and report a terminal status; an accepted trigger is not deployment success.

Tasks:
1. Add failing integration tests for atomic start, release/task/deployment completion, cancel/reject, retry and duplicate requests.
2. Add fenced renewable leases and persisted deployment operations; test long work, lease loss, recovery and partial success.
3. Route all API/UI release commands through the engine; import pending legacy jobs, quarantine ambiguous running jobs for explicit recovery.
4. Run full Go tests, race checks, vet, frontend typecheck/build; independent review of transaction, concurrency and recovery boundaries.

Verification uses isolated SQLite databases; optional PostgreSQL concurrency tests use FLUXA_TEST_POSTGRES_DSN, never application credentials. Production migration is delivered but not applied. Exactly-once external side effects require the executor's durable idempotency contract.

Decisions and limits:
- Unknown deployment outcomes retain the same persisted operation key. Only a confirmed failure permits a new operation; successful services are skipped on retry. Future real executors must durably honor this key across restarts.
- Untracked pre-upgrade executions are paused for explicit reconciliation/retry. Their old external effects cannot be retroactively deduplicated.
- Cancellation fences local progress and cancels the executor context; it does not claim to roll back an already accepted external deployment.
- Publish/retry now return execution payloads; the frontend and README were updated together. Historical job reads remain available.
- Existing layout edits were preserved. No commit, deployment or live database mutation was performed.
